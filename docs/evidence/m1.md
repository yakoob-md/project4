# M1 storage and ingestion

Build and start the PostgreSQL and M0 protocol services with:

```powershell
docker compose up -d --build postgres mcp-tools literature-adk review-worker
```

Run the worker's migration and fixture checks, then invoke the public-paper smoke separately.

```powershell
powershell -NoProfile -File scripts/test_m1_ingestion.ps1
powershell -NoProfile -File scripts/test_m1_ingestion.ps1 -Live
```

The worker calls `services.review_worker.ingestion.ingest` with the authenticated caller's owner ID, run ID, cutoff, query, and either PDF bytes or pasted text. The migration keeps these records in the `paperlens_m1` schema alongside the existing local workflow. A downstream consumer calls `load_bundle(owner_id, bundle_id)` or `search_passages(owner_id, bundle_id, query)`. Pass a 384-dimensional batch embedder at ingestion and a same-model query embedding at search to enable hybrid ranking. Keyword retrieval runs by default. The database combines up to 50 candidates per ranker using reciprocal rank fusion and returns at most 20 results.

PDF offsets are zero-based character indices within extracted page text. Pasted-text offsets are relative to the identified paragraph. Abstract offsets are relative to the retrieved abstract. All end offsets are exclusive. The report storage boundary matches passage ID, locator, both offsets, and the verbatim text against the saved bundle before committing the report and its findings in one transaction.

The current path uses arXiv abstracts, deduplicated by arXiv version family and normalized title. It distinguishes unavailable providers from successful searches with no results. OpenAlex, OCR, full-text acquisition, and deployment of an embedding model remain outside this slice. The worker interface is internal. UI and specialist wiring remain future work.

Use the [blank human-labelling template](../../evaluation/human_labelling_template.md) before reviewers see model outputs.
